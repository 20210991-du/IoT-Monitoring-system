# ADR-010 · 인증(로그인/회원가입/승인) 백엔드 인터페이스 명세

## 맥락

- 기존 `Login.jsx` 는 하드코딩 `admin.siwon` / `siwonpass!` 1초 타임아웃 통과로 동작 (데모용)
- 회원가입 페이지 자체가 없었음
- 백엔드(`backend/main.py`) 도 인증 엔드포인트 미구현 — 현재 7종(`/api/health`, `/api/devices`, `/api/anomalies`, `/api/insights`, `/api/predict/{id}`, `/api/summary`, `/api/upload`) 모두 비인증
- 박지훈은 팀 repo 의 `backend/` 를 단독 수정 X (시원팀 합의 필수)
- **추가 요구**: 산업 관제 시스템 컨셉 — 일반 공개 가입 X, **관리자 승인을 받은 사람만** 로그인 가능

→ **프론트는 localStorage 기반 mock 으로 선반영, 백엔드 인터페이스는 본 ADR 로 박아두고 7차 회의 안건으로 승격.**

## 가입 워크플로우 (승인 기반)

```
[누군가 회원가입]
       ↓
   status = "pending"  ← DB 에 저장
       ↓
   로그인 시도 → 차단 ("관리자 승인 대기 중")
       ↓
[관리자가 운영자 관리 페이지에서]
   ├─ 승인 → status = "active"  → 로그인 허용
   └─ 반려 → status = "rejected" + 사유  → 로그인 차단 (사유 표시)
       ↓
   (반려된 계정도 admin 이 "재심사" 로 다시 pending 가능)
```

## 사용자 상태 (status 필드)

| 상태 | 의미 | 로그인 가능? |
|---|---|---|
| `pending` | 가입 신청, 관리자 승인 대기 | ❌ |
| `active` | 승인 완료, 정상 사용 | ✅ |
| `rejected` | 관리자 반려 (사유 포함 가능) | ❌ |

### 백엔드 (제안, 7차 회의 합의 필요)

다음 11 엔드포인트 신설 + JWT 기반 보호:

```
# 사용자 본인용
POST /api/auth/signup
POST /api/auth/login
POST /api/auth/logout
GET  /api/auth/me
POST /api/auth/password/reset/request
POST /api/auth/password/reset/verify
POST /api/auth/password/reset/confirm

# 관리자 전용 (admin role + JWT 필수)
GET    /api/admin/users                 # 전체 조회 + status 필터
POST   /api/admin/users/{id}/approve    # 승인 → active
POST   /api/admin/users/{id}/reject     # 반려 → rejected (body: {reason})
POST   /api/admin/users/{id}/reactivate # 재심사 → pending
```

기존 7 엔드포인트는 `Authorization: Bearer <jwt>` 필수로 전환. admin 전용 4종은 추가로 `role=admin` 검증.

## 인터페이스 명세

### 1. POST `/api/auth/signup`

**Request:**
```json
{
  "id":    "kim.operator",
  "pw":    "abcd1234!",
  "name":  "김운영",
  "email": "[비공개메일]",
  "role":  "operator"
}
```

**Response 201:**
```json
{
  "ok":      true,
  "pending": true,
  "user":    {
    "id":         "kim.operator",
    "name":       "김운영",
    "email":      "[비공개메일]",
    "role":       "operator",
    "status":     "pending",
    "created_at": "2026-05-04T15:00:00Z"
  },
  "message": "관리자 승인 후 로그인할 수 있습니다."
}
```

**Response 400:** `{ "ok": false, "error": "이미 사용 중인 ID 입니다.", "field": "id" }`

> **주의**: signup 응답에는 `token` 미포함 (자동 로그인 X). pending 상태에선 인증 토큰 발급 안 함.

### 2. POST `/api/auth/login`

**Request:** `{ "id": "...", "pw": "..." }`

**Response 200 (status=active 만):**
```json
{
  "ok":    true,
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user":  {
    "id": "...", "name": "...", "role": "operator", "email": "...",
    "status": "active"
  }
}
```

**Response 401 (자격 실패):** `{ "ok": false, "error": "ID 또는 비밀번호가 일치하지 않습니다." }`

**Response 403 (status=pending):**
```json
{
  "ok":     false,
  "status": "pending",
  "error":  "관리자 승인 대기 중인 계정입니다. 승인 완료 후 로그인할 수 있습니다."
}
```

**Response 403 (status=rejected):**
```json
{
  "ok":     false,
  "status": "rejected",
  "reason": "등록되지 않은 외부 인원입니다.",
  "error":  "가입이 반려된 계정입니다. 관리자에게 문의해 주세요."
}
```

### 3. POST `/api/auth/logout`

헤더에 토큰. 응답 `{ "ok": true }`. 서버 측 블랙리스트 / 토큰 만료 처리는 구현 자율.

### 4. GET `/api/auth/me`

헤더에 토큰. 응답 `{ "user": {...} }` 또는 401.

### 5. POST `/api/auth/password/reset/request`

비밀번호 재설정 코드 발급 + 이메일 발송 (서버측 SMTP).

**Request:** `{ "email": "[비공개메일]" }`

**Response 200 (always):**
```json
{ "ok": true, "expires_at": "2026-05-04T15:10:00Z", "masked_id": "ki**********" }
```

> **보안**: 이메일 등록 여부와 관계없이 200 + 동일 응답 형태(이메일 열거 공격 방지). 로그에만 실제 매칭 여부 기록. 단 mock 환경(`authMock.js`) 은 데모 편의를 위해 등록 안 된 이메일에 에러 반환 — 운영 시 정책 재검토.

**Rate-limit**: 동일 이메일/IP 1분당 1회.

### 6. POST `/api/auth/password/reset/verify`

코드만 사전 검증 (UI step2). 백엔드는 검증만 하고 토큰은 발급하지 않거나, 1회용 짧은 reset 토큰 발급도 가능.

**Request:** `{ "email": "...", "code": "123456" }`

**Response 200:** `{ "ok": true }` (또는 `{ "ok": true, "reset_token": "..." }`)

**Response 400:** `{ "ok": false, "error": "코드가 일치하지 않습니다." }`

### 7. POST `/api/auth/password/reset/confirm`

최종 비밀번호 변경.

**Request:** `{ "email": "...", "code": "123456", "pw": "newpass1!" }`

**Response 200:** `{ "ok": true }`  
**Response 400:** `{ "ok": false, "error": "코드가 만료되었습니다.", "field": "code" }`

비번 변경 후 해당 사용자의 기존 access 토큰 일괄 무효화 권장 (refresh 블랙리스트 또는 password_changed_at 타임스탬프 비교).

### 8. GET `/api/admin/users` (admin only)

**Query:** `?status=pending|active|rejected` (옵션, 미지정 시 전체)

**Response 200:**
```json
{
  "ok": true,
  "users": [
    {
      "id": "kim.operator", "name": "김운영", "email": "[비공개메일]",
      "role": "operator", "status": "pending",
      "created_at": "2026-05-04T15:00:00Z",
      "approved_at": null, "approved_by": null,
      "rejected_at": null, "rejected_by": null, "rejected_reason": null
    }
  ]
}
```

**Response 403 (admin 아님):** `{ "ok": false, "error": "관리자 권한이 필요합니다." }`

### 9. POST `/api/admin/users/{id}/approve`

**Response 200:** `{ "ok": true, "user": { ..., "status": "active", "approved_at": "...", "approved_by": "admin.siwon" } }`

승인 시 부수효과(권장):
- 본인에게 이메일 발송 ("승인 완료, 로그인 가능합니다")
- audit log 기록

### 10. POST `/api/admin/users/{id}/reject`

**Request:** `{ "reason": "등록되지 않은 외부 인원입니다." }` (옵션)

**Response 200:** `{ "ok": true, "user": { ..., "status": "rejected", "rejected_reason": "...", "rejected_at": "...", "rejected_by": "admin.siwon" } }`

**Response 400:** `{ "ok": false, "error": "본인 계정은 반려할 수 없습니다." }` (admin 자기자신 보호)

### 11. POST `/api/admin/users/{id}/reactivate`

반려된 계정을 다시 pending 으로 되돌림. **Response 200:** `{ "ok": true, "user": { ..., "status": "pending" } }`

## 검증 규칙 (프론트·백엔드 동일)

| 필드 | 규칙 |
|---|---|
| `id` | 영문으로 시작, `[a-zA-Z0-9._-]`, 4~20자 |
| `pw` | 영문+숫자 포함, 8자 이상 |
| `name` | 한글/영문, 2~20자 |
| `email` | 표준 RFC 형식 |
| `role` | `admin` / `operator` / `viewer` 중 하나 |

## 보안 권장

- 비밀번호: [비공개] 또는 argon2id
- JWT: [비공개] + 비밀키는 `.env` (`JWT_SECRET [비공개]
- 만료: access 1h, refresh 7d (단순 단일 토큰 30분도 캡스톤 범위에선 OK)
- HTTPS 필수 (사설 서버 Cloudflare Tunnel 자동 HTTPS 충족)
