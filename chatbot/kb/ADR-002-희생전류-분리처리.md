# ADR-002 · 희생전류는 2개 기기 전용 변수로 분리 ⛔ DEPRECATED

> **2026-05-26 9차 회의 결정**으로 폐기. 본 결정의 도메인 사실 (희생양극 단말이 TB24-250406, TB24-250407 2대만 해당) 은 유효하지만, AI 모델 분리 처리는 [[ADR-018-희생양극-분리모델-폐기-통합모델-단일화]] 로 단일 통합 모델로 전환됨. 이 ADR 은 historical 보존.

## 맥락

- 55개 장비 중 **TB24-250406, TB24-250407** 2개만 희생전류 값이 측정됨
- 나머지 53개는 해당 값 자체가 없음 (NaN / 0)

## 회사(OmniSolution) 답변

> TB24-250406, TB24-250407 2개만 **희생양극 방식** 사용.
> 나머지는 **외부전원 방식**이므로 희생전류 항목 자체가 해당 없음.

→ [[회사_QA로그#Q2]]

## 결정

- 희생전류는 **공통 LSTM 모델 입력에서 제외**
- 해당 2개 기기에 한해 **전용 변수**로 분리 취급
- 이 2개 기기는 별도 판정 로직 검토 (추후)

## 근거

- 53개 장비에 대해 0/NaN 으로 채우면 **의미 없는 노이즈**만 추가됨
- "방식 자체가 다른 설비"를 하나의 모델로 묶는 건 개념적으로 부적절
- 공통 모델 정확도 보호가 우선

## 파급

- 공통 모델 입력 피처: **6 → 4 (방식전위/AC유입/온도/습도)**
- UI 의 장비 상세에서 희생전류 칸은 해당 2개 기기에만 표시하거나 "N/A" 처리
- Figma 디자인 점검 필요: [[프론트엔드]]

## 구현 현황

- **설계 결정**: ✅ 완료
- **코드 반영**: ✅ **완료** (v2026.04.19)
  - `SACRIFICIAL_DEVICES = ["TB24-250406", "TB24-250407"]` 상수 도입
  - `SACRIFICIAL_FEATURES` 별도 분리
  - `get_sacrificial_device_data()` 함수 — 2 기기 전용 데이터 반환
  - `BASE_FEATURES` 에서 희생전류 제외
- 구현 파일: `gas_common_model_train(2026.04.14).py`, `gas_common_model_predict(2026.04.14).py`
- 반영 CHANGELOG: v2026.04.19 Added 블록
