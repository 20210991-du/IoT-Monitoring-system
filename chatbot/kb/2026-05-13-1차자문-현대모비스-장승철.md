## Q1 · 이상 탐지 false positive 허용 비율

**질문 요지:** LSTM AE threshold 튜닝 시 미탐 vs 오탐 어느 쪽을 더 보수적으로?

**자문:**
> Project 성격에 따라 다름. **자율주행(ADAS) 등 안전 임계(safety-critical)** 설비는 **오탐 감수하더라도 False Negative 더 보수적**.
>
> 정답은 없으니 방법론적으로 접근:
> - **threshold 단일 X, 2-tier (Warning/Critical) 구조 권장**
> - **Critical** = FPR 보수적 관리 (오탐 적게)
> - **Warning** (대시보드 표시) = 상위 허용, 놓치지 않되 강제 주의 X
> - Warning 은 분석하면서 오탐률 지속 관리

**우리 적용 상태:**
- ✅ 이미 5단계로 구현 (정상 / 위험 / 이상 의심 / 통신 장애)
- ✅ Critical (위험) — 알람띠 + 펄스 + 챗봇 자동 KPI 30s (강제 주의)
- ✅ Warn (이상 의심) — 핀·표 표시만, 강제 주의 X
- → **자문 권장 2-tier 와 정합!** ADR-011 결정 (5→5단계 단순화) 가 자문에 부합.

## Q2 · 대시보드 화면 구성·정보 배치 최적화

**자문:**
> 한 화면에 모든 정보 X. **Overview → Detail 으로 depth 분리** 가 기본 효과적.
> - Overview: critical section 하이라이트 + 현황 요약
> - Detail: 한 단계 더 들어가서 디테일
>
> 관리자 다수·공유 인원 대상이면 더더욱 한 화면 정보 과다 비효율.

**우리 적용 상태:**
- ✅ Overview: KPI 카드 + 지도 + 표 요약 + 챗봇
- ✅ Detail: AnalysisModal (MSE 차트 등 클릭 시)
- ✅ Equipment 페이지 (정렬·필터·검색) 별도 depth
- → 자문 방향 부합. **다만 Detail 진입 동선이 약함 (모달 외 다른 경로)** — 회의에서 더 명확한 "상세 보기" 버튼 검토.

## Q3 · 시계열 시각화 개선 (★ 가장 구체적 액션)

**자문 (4가지 구체 권장):**

1. **이상 구간 오버레이** — 시계열 위 "이상 탐지된 시간대"를 **반투명 빨간 배경** 으로 깔기
   → 수백 개 데이터 포인트 중 어디 봐야 하는지 즉시 인지

2. **정상 범위 밴드 (Confidence Band)** — LSTM AE reconstruction 의 "정상 범위"를 **회색 밴드** 로 표시, 실제 값이 밴드 벗어나면 강조
   → threshold 수평선 하나보다 훨씬 직관

3. **이벤트 마커** — 센서 값 변화만 X, **시스템 이벤트 (밸브 열림, 작업자 출입 등)** 를 같은 시간축에 마커
   → 차량 분석에서도 "STR resume", "user switch" 같은 시스템 이벤트 같이 찍어야 인과 보임
   → IoT 관제: "밸브 열림", "작업자 출입" 등 적용 가능

4. **시간 범위 토글** — **실시간(1h) / 단기(24h) / 장기(7d)** 필수
   → 이상 탐지 확인은 단기, 추세 분석은 장기

**우리 적용 상태 + Action:**
- ✅ MSE 추이 차트 있음 (AnalysisModal)
- ✅ 임계선 수평선 (위험/이상 의심)
- ❌ 이상 구간 오버레이 — **추가 필요** (간단)
- ❌ Confidence Band — **추가 필요** (이두현 모델 결과 필요)
- ❌ 이벤트 마커 — **추가 필요** (이재헌 backend 이벤트 로그 필요)
- ❌ 시간 범위 토글 — **추가 필요** (1h/24h/7d) — UI 만 박지훈

## Q4 · 이상 데이터 혼입 시 모델 신뢰도 평가

**자문:**
> 입력이 오염되면 결과는 X. **LSTM AE 학습 전 데이터 클렌징 파이프라인 별도 구성**.
> - 통계적 이상치 (IQR 3σ 밖) 제거
> - 센서 결측 구간 마킹
> - 수동 라벨링 가능하면 소량이라도 확보
>
> 평가 방법:
> - **검증용 확실한 정상 데이터** 에 **의도적으로 오류 주입** → 탐지율 측정·개선

**적용 영역:** 이두현 (AI 모델). 박지훈 직접 X.

**Action (이두현):**
- [ ] 데이터 클렌징 파이프라인 명시 (IQR 3σ, 결측 마킹, 수동 라벨)
- [ ] 검증 데이터셋 별도 마련 (의도적 이상 주입)
- [ ] 평가 지표 정의 (탐지율 + FPR + FNR)

## Q5 · LLM 신뢰성 확보 (★ 우리 챗봇 직접 관련)

**자문 (멘토 본인 차량 RCA LLM 시스템 기반 매우 실무적):**

1. **심각도 × 분석 가능성 매트릭스로 필터링**
   - Critical × 로그 첨부 여부 매트릭스로 선별

2. **LLM 입력 제한**
   - 모든 데이터 X → **관련 로그 구간만 추출** 해서 넣어야 정확도 ↑

3. **시스템 프롬프트로 추측 금지**
   - LLM 이 로그에 없는 내용 추측 금지 명시
   - **제시한 원인을 실제 소스(AOSP)와 대조 확인** → 코드에서 확인 안 되면 **"추정" 으로 격하**

4. **모든 분석 결론에 근거 의무 기재**

**우리 적용 상태 + Action:**

| 자문 권장 | 우리 현재 | 액션 |
|---|---|---|
| 심각도 × 분석 가능성 매트릭스 | 키워드 매칭만 | ⏳ 매트릭스 기반 분기 추가 |
| 관련 데이터만 추출 | ✅ trends·counts·날씨만 주입 | — |
| 추측 금지 시스템 프롬프트 | ✅ "환각 금지" 명시 | 강화 가능 |
| 출처·소스 대조 | ✅ 노드 ID 인용 강제 | "데이터 출처" 명시 |
| 추정 격하 | 부분적 ("확인되지 않음") | ⏳ **"[추정]" 라벨** 명시 |
| 근거 의무 기재 | 부분적 | ⏳ **"근거: MSE 0.91 @ TB24-5JN011"** 형식 강화 |

**Action (박지훈, 이번 주):**
- [ ] 시스템 프롬프트 강화 — 응답마다 "근거(노드 ID, MSE, 시각)" 의무 기재
- [ ] 추정 라벨 — 모호한 답변 시 "[추정]" prefix 자동 부착 유도
- [ ] 챗봇 응답 UI — "근거" 섹션 확장형 (선택)
