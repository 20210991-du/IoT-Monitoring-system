# ADR-018 · 희생양극 분리 모델 폐기 → 통합 모델 단일화

## 맥락

[[ADR-002-희생전류-분리처리]] 에서 결정된 "**희생전류 피처 + 희생양극 전용 모델 분리 처리**" 가 발표 D-6 시점에서 실효성 문제.

### 이두현 보고 (2026-05-26 9차 회의)
- F1 스코어로 모델 신뢰성 평가 시도
- **일반(통합) 모델**: F1 양호 (높음)
- **희생양극 전용 모델 (TB24-250406, TB24-250407 2대)**: F1 **20~30** 으로 매우 낮음
- 별짓 다 해봤는데 수치 안 올라감
- 원인 추측: **전처리 과정** 또는 **입력 데이터** 문제 (2 단말만으로 학습 → 데이터 부족 가능성)
- 발표 (6/1, D-6) 까지 해결 불가능

### 의사결정 옵션
- (A) 희생양극 전용 모델 보강 — F1 끌어올리기. 발표 전 불가능
- (B) 두 모델 유지하되 희생양극은 낮은 F1 그대로 발표 — 신뢰도 손상
- (C) **희생전류 피처 자체를 제외하고 통합 모델 1개로** — 발표 안전, 졸업 후 재검토

## 결정

**옵션 (C) 채택** — 통합 모델 단일화.

### 변경 사항 (이두현, 2026-05-27 commit `1bdf3c3` + 선행 다수)
- `ai/scripts/gas_unified_model_train.py` — 402줄 → ~120줄 (분리 모델 코드 전체 제거)
- `ai/config/model_config.json`:
  - `sacrificial_devices` (TB24-250406, TB24-250407) **필드 제거**
  - `sacrificial_features` ("희생전류") **필드 제거**
  - `best_tuned_threshold`: 0.00046 → **0.00026** (통합 모델 재학습 결과)
- `ai/config/device_thresholds.json` — 55 단말 threshold **모두 통합 모델 기준 재산정**
- `ai/models/common_lstm_autoencoder.keras` + `group_scalers.pkl` 새 가중치
- 별도 희생양극 학습/예측 스크립트 폐기

### 챗봇 / 서버 영향
- `server.js`: `MODEL_CONFIG?.sacrificial_devices?.includes(...)` 옵셔널 체이닝이라 **crash 없음**. `isSacrificial` 필드만 항상 `false` 가 됨 (의도된 결과)
- 챗봇이 자동으로 새 threshold 인용 — 검증: "TB24-250401 정상 한계는?" → "MSE < 0.000062" 정상 답변

### 도메인 사실 (시스템 프롬프트에 유지)
- 희생양극 방식 단말은 **TB24-250406, TB24-250407 2대만** 해당이라는 도메인 사실 자체는 변하지 않음
- 다만 AI 모델 분리는 폐기 — 통합 모델이 8 센서 (희생전류 제외) 로 모두 학습

## 트레이드오프

### 장점
- **F1 스코어 일관** — 통합 모델 단일 평가
- **유지보수 단순** — 모델 1개, 분기 코드 제거
- **발표 안전성 ↑** — D-6 시점 안전 우선
- **희생전류 피처 자체 제외** — 두 단말 외에는 의미 없는 피처

### 단점
- **희생양극 단말 특화 탐지 손실** — 두 단말의 희생전류 변동을 못 잡음
- 옴니솔루션 도메인 권고 (희생전류 분리 처리) 와 어긋남 (단기 트레이드오프)
