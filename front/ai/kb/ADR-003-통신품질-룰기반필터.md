# ADR-003 · 통신품질은 룰 기반 필터, AI 입력 제외

## 맥락

- 통신품질(dBm)은 원래 6개 센서 중 하나로 고려되었음
- 하지만 수치 자체가 **실제 학습 데이터에 미포함** (회사 확인)
- 외부 요인(주차/공사/강우)이 크게 작용 — 모델이 학습하기 어려운 노이즈

## 회사 답변

> **-115 dBm 이하 = 통신 불가**.
> 단, 이 수치는 데이터로 수집되지 않음.
> 핵심은 수치가 아니라 **통신 단절 이벤트**.
> 과거 이력·주변 기기 상태·강우 데이터 조합으로 **일시 장애 vs. 고장** 구분이 필요.

→ [[회사_QA로그#Q4]]

## 결정

- 통신품질은 **LSTM AE 입력에서 제외**
- 별도 **룰 기반 필터**로 처리
  - `-115 dBm 이하` → 통신 불가 플래그
  - 통신 단절 **이벤트** 를 별도로 생성 (연속 결측 등)
- 향후 기상 데이터(강우) 연계해서 일시 장애 vs. 고장 구분

## 근거

- 수치 자체가 학습셋에 없으니 AI 입력으로 쓸 근거 약함
- 통신 이슈는 **시계열 이상**이 아니라 **외부 환경 이벤트** — 다른 클래스의 문제
- 룰 기반으로 명확히 분리해야 UI 에서도 "통신 장애"를 독립 상태로 표시 가능
