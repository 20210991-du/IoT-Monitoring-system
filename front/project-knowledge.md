# 프로젝트 지식베이스 — 개발자 문의 봇용

> 이 문서는 "개발자 문의" 채팅방의 AI가 프로젝트를 설명할 때 쓰는 지식 소스입니다.
> 박지훈의 옵시디언 프로젝트 노트(개요·현재상태·AI컨텍스트·용어집)를 공개 가능한 범위로 정리한 스냅샷입니다.
> ⚠️ 운영 비밀(비밀번호·SSH·내부 IP·DB 자격증명)은 포함하지 않습니다. 그런 걸 물으면 "보안상 공개하지 않는다"고 답하세요.

---

## 1. 한 줄 소개
**매설배관 AI 통합관제 시스템** — 도시가스 지하 배관에 설치된 IoT 센서 데이터를 통합 수집하고, **LSTM-AutoEncoder로 이상을 자동 탐지**하며, 실시간 알림·지도·AI 챗봇으로 관리자의 운영 의사결정을 돕는 **지능형 통합관제 플랫폼**.

## 2. 프로젝트 맥락
- **유형**: 호서대학교 컴퓨터공학부 졸업 프로젝트(캡스톤), 기업 연계형.
- **팀**: "시원" 팀 3인 (이재헌, 박지훈, 이두현).
- **실데이터 파트너**: ㈜옴니솔루션(OmniSolution) — 실제 도시가스 배관 모니터링(KSCG) 데이터 제공.
- **대상**: 군산 지역 매설배관 55개 감시 단말(Terminal Box, `TB24-250401~455`).
- **성격**: 단순 "모니터링 화면"이 아니라, 산업용 IIoT 통합관제 플랫폼을 학생 프로젝트 규모로 구현한 것.

## 3. 주제 3축
1. **통합관제** — 분산된 IoT/설비 데이터를 한 화면에서 본다.
2. **AI 기반 이상탐지** — 비정상 패턴을 자동 판별한다.
3. **운영 지원** — 알림·이력·요약·대화형 AI로 관리자 의사결정을 돕는다.

## 4. 시스템 아키텍처 (실제 운영 기준)
```
옴니솔루션 KSCG (MS SQL Server, read-only)
  → siwon MySQL 미러 (Mac Studio, 약 213만 row, 자동 sync: 알람 1h / 센서 2h / 메타 6h)
    → Express 통합 서버 (Node.js, 정적 dist + REST API, 단일 origin)
      ├→ React 18 + Vite 대시보드 (관제 화면)
      ├→ LSTM-AutoEncoder 이상탐지 (Python, ai_predictions 테이블 적재)
      └→ LLM 챗봇 (Ollama qwen3.5:9b 로컬 + OpenAI GPT 선택, Function Calling)
  → Cloudflare Named Tunnel → 영구 도메인(공개 URL)로 서비스
```
- 라이브 서비스는 Mac Studio(M2 Max)에서 launchd로 상시 가동, Cloudflare Named Tunnel로 영구 도메인에 노출.
- 참고: 초기 설계는 Next.js + FastAPI였으나, 통합 시연 환경은 Express + React/Vite로 단일화해 운영 중. FastAPI 백엔드(이재헌, 7개 엔드포인트)도 별도 존재.

## 5. 기술 스택 (실제)
- **프론트엔드**: React 18.3 + Vite 5, Plain JSX, CSS 변수 + 인라인 스타일(별도 CSS 프레임워크 없음), 상태는 useState + localStorage.
- **백엔드**: Node.js + Express (`server.js`), REST + SSE 스트리밍.
- **DB**: MySQL(siwon) — 옴니 KSCG(MS SQL)를 미러링.
- **AI 이상탐지**: LSTM-AutoEncoder (TensorFlow 2.16, Python 3.12).
- **LLM**: Ollama 로컬(qwen3.5:9b, qwen3:14b, qwen3.5:27b) + OpenAI(gpt-4o-mini, gpt-5, gpt-5.5) 선택.
- **지도**: Leaflet + OpenStreetMap (지명검색 Nominatim, 거리계산 Haversine).
- **인프라**: Mac Studio + launchd + Cloudflare Named Tunnel.
- **날씨**: Open-Meteo (실시간 + 예보 + 과거 아카이브, 군산 좌표).

## 6. AI 이상탐지 (핵심)
- **모델**: 공통 **LSTM-AutoEncoder 1개** + 장비별 Threshold (초기엔 희생양극 분리 모델도 검토했으나 성능(F1 20~30)이 낮아 2026-05 통합 모델 단일화로 폐기).
- **원리**: 시계열을 인코딩→복원하고, 재구성 오차(**MSE**)가 크면 이상으로 판정.
- **Threshold**: 장비별 99th percentile 기준으로 산출. 위험도 = MSE가 threshold의 **70% 미만=정상 / 70~100%=관찰 / 100% 초과=이상**.
- **입력 피처**: 방식전위·AC유입·온도·습도·통신품질 등 + 파생 피처(`diff1` 직전값 차이, `dev24` 24시간 이동평균 대비 편차). seq_len 보통 24(=24시간).
- **센서 기여도(Feature Contribution)**: 전체 MSE 중 센서별 비율 → 이상 원인 태그(예: "습도 편차 이상")의 근거.
- 예측 결과는 `ai_predictions` 테이블에 적재되어 대시보드/요약/이상탐지/챗봇이 모두 같은 AI 기준으로 일원화됨.
- **통신품질**은 룰 기반 필터로 처리(AI 입력에서 제외). 그룹핑 기준은 **정류기(Rectifier) 단위**.

## 7. AI 챗봇 (Function Calling)
관제 데이터를 자연어로 묻고 답하는 어시스턴트. 단순 챗봇이 아니라 **DB를 직접 조회하는 도구(Function Calling)**를 갖춤.
- **도구 20개**: 단말 조회(목록·상세·이력·집계·값검색·구역요약·비교·최근변화·점검이력·예측), 현황요약, 위치(DB검색·지명좌표·주변단말), AI 모델정보, **자가확장 2개**(`execute_safe_sql` 자유 SQL + `describe_table` 스키마 탐색), **날씨 2개**(예보 최대 7일 + 과거 최대 1년).
- **자가확장 SQL**: 미리 정의된 도구로 답이 안 되는 임의 분석 질문도 LLM이 직접 안전한 SELECT를 작성해 답함(5단 안전장치: 키워드 화이트리스트·정규식·단일 statement·LIMIT·타임아웃).
- **스트리밍**: SSE로 토큰·도구호출·세션·완료 이벤트 실시간 전송. 생성 중 토큰/속도 표시 + 중지 버튼.
- **모델 선택**: 로컬(빠름/균형/고품질) ↔ GPT(외부) 전환. 메시지마다 모델·토큰량 기록.
- **영구 저장**: 대화는 `chat_sessions` + `chat_messages`에 저장(세션별 제목·고정·이름변경·검색·소프트삭제). 사용자 계정별 분리.
- **위치·지도·KPI 연동**: 답변 속 단말 ID → 지도 자동 줌, 상태 → KPI 자동 필터.
- **표현 가드**: 센서 기준과 AI 기준 혼용 금지, "AI 기준 대비 N배" 표현, 숫자 판정 가드(예: AC유입 971mV를 "500mV 초과 471mV"로 정확히) 등 답변 품질 장치.

## 8. 주요 기능
- **실시간 대시보드**: KPI 카운트(정상/위험/이상의심/통신장애), 지도, 장비표, AI 탐지 목록, 시스템 로그.
- **지도**: Leaflet 기반, 단말 위치·상태 마커, 위험 단말 레이더 펄스 강조.
- **데모 모드**: 실데이터가 평온할 때 시연 임팩트를 위해 가상 장비 10대(위험3·이상의심4·통신장애3)를 토글로 추가(OFF 시 흔적 없음).
- **시스템 로그**: 알람·AI예측·DB sync·도구호출 4종 이벤트 통합 표시, 옴니→Mac Studio 미러링 수신 기록.
- **인증/관리자**: 회원가입·로그인·승인(JWT 쿠키), 관리자 페이지(사용자 관리·챗봇 통계·토큰 사용량·로그인 로그·문의함).
- **문의 채널**: 관리자 문의(문의·버그 신고) + 개발자 문의(이 방, 프로젝트 설명). AI 답변 + 운영자/개발자 직접 답변.

## 9. 도메인 용어 (배관 방식 모니터링)
- **방식전위(Cathodic Protection Potential)**: 배관 부식 방지 전위. 기준값(보통 -850mV) 이하 유지 필요. 벗어나면 부식 위험.
- **AC유입**: 인접 송전선 등 외부 교류 간섭으로 배관에 유도되는 교류 전압(mV). 높으면 절연 파손 가능.
- **희생전류 / 희생양극 방식**: 더 쉽게 부식되는 금속(Mg/Zn)을 양극으로 붙여 배관 보호. 본 데이터 55개 중 2개만 해당. (전류가 0에 가까우면 방식 기능 상실)
- **외부전원 방식 / 정류기**: 외부 정류기로 직류를 공급해 배관 보호. 본 데이터 대부분. 정류기는 그룹핑 기준 단위.
- **맨홀**: 지하 배관 점검 공간. 단말의 온도/습도 환경 기준. 침수 시 습도 급상승 + 통신 불안.
- **MSE / Threshold / Feature Contribution**: (위 6번 참조)
